# AI 示意图缩略图选中居中设计

## 背景

AI 示意图页面的候选视角按房间分组，并放置在可横向滚动的缩略图轨道中。当前选中视角时调用 `Element.scrollIntoView()`，但缩略图位于多层房间分组节点内部，浏览器无法稳定地以最外层横向轨道为基准完成居中，导致用户难以连续查看当前视角前后的候选项。

## 目标

- 中间位置的候选视角被选中后，平滑滚动到缩略图轨道的可视区域中央。
- 位于列表两端的候选视角遵守滚动边界，不为强制居中制造额外空白。
- 缩略图点击、小地图选择和前后视角切换使用完全一致的滚动行为。
- 用户仍可自由手动横向滚动缩略图轨道，不启用会抢夺滚动位置的强制吸附。

## 设计

`AiViewFilmstrip` 继续负责缩略图定位和滚动。选中视角后：

1. 从 filmstrip 容器中定位 `.ai-view-track` 和目标 `data-view-id` 卡片。
2. 使用轨道与卡片的可视矩形计算二者中心点的水平差值。
3. 将中心差值加到轨道当前 `scrollLeft`，得到目标滚动位置。
4. 将目标值限制在 `0` 到 `scrollWidth - clientWidth` 范围内。
5. 调用轨道自身的 `scrollTo({ left, behavior: 'smooth' })`。

采用相对可视矩形计算，可以正确处理房间分组造成的多层节点和间距，不依赖卡片的直接父节点或 `offsetParent`。

## 交互入口

所有激活候选视角的入口继续统一调用 `AiConceptApp.selectView()`：

- 点击缩略图。
- 点击小地图点位。
- 点击上一视角、下一视角按钮。

`selectView()` 完成状态切换后调用 `filmstrip.scrollViewIntoView(id)`，因此无需在各入口重复实现滚动逻辑。

## 边界与降级

- 第一项和最后一项通过滚动范围钳制自然靠边显示。
- 轨道、目标卡片或浏览器滚动 API 缺失时安全返回，不影响视角切换。
- 当内容宽度不超过轨道可视宽度时，滚动位置保持为 `0`。
- 保留平滑滚动；不增加 CSS `scroll-snap`，避免干扰用户手动浏览。

## 验证

- 单元测试验证中间项的目标滚动值能使其中心与轨道中心对齐。
- 单元测试验证首项钳制为 `0`，末项钳制为最大滚动值。
- 应用测试验证缩略图、小地图与前后切换均激活目标视角并触发同一居中方法。
- 浏览器验证选中中间项后其前后缩略图均可见，首尾项没有多余空白。
