# AI 方向示意图生图条件与 GPT Image 2 任务设计

## 1. 背景与目标

AI 方向示意图页面已经具备候选视角生成、白模预览、微调、自定义视角、删除和恢复能力。本阶段补齐“生图条件”弹窗，并接入真实的 OpenAI 图像编辑流程。

设计师确认候选视角后，可以选择一个或多个装修风格及光照环境。系统将每个合法白模视角与所选条件组成任务矩阵，使用 `gpt-image-2` 在保留原始空间构图的前提下生成可追溯的装修方向示意图。

本设计只修改 `occt_demo`，不修改 CAD Plugin。浏览器不直接持有 OpenAI API Key，也不直接跨域请求 OpenAI。

## 2. 产品边界

本阶段包含：

- 中央式生图条件弹窗。
- 十二种装修风格的本地目录与自有示意图。
- 四种光照环境。
- 条件组合计数和单次上限校验。
- 白模视角截图采集。
- Node 同源 API 代理。
- `gpt-image-2` 图像编辑任务拆分、执行、持久化、取消和失败重试。
- 任务进度及白模/结果关联所需的数据契约。

本阶段不包含：

- 训练或微调图像模型。
- 复制酷家乐的图片、提示词、私有接口或受版权保护的素材。
- 修改 CAD Plugin 的 C++ 桥接。
- 客户偏好确认和最终交付级效果图流程。

## 3. 设计原则

- 所有合法视角自动参与生成，不重新引入手动视角勾选。
- 风格通过真实室内参考图表达，不能只显示文字或彩平图。
- 风格、环境均支持多选，并始终显示预计生成数量。
- 每个组合是独立、可追溯、可重试的任务项。
- 不伪造成功状态；没有有效密钥或真实接口结果时，不显示生成成功。
- API Key 只存在于 Node 进程环境变量中。
- 前端只访问同源 `/api/ai-concept/*`，不关闭浏览器安全策略。
- 生成结果属于“方向示意图”，不等同于最终效果图。

## 4. 页面与交互

### 4.1 弹窗布局

点击“下一步：生图条件”后，在当前白模页面上打开中央 Liquid Glass 弹窗。弹窗不切走当前页面，以便设计师保留候选视角上下文。

弹窗结构从上到下为：

1. 标题和参与生成的有效视角数量。
2. 装修风格图片卡片区。
3. 光照环境选项区。
4. 组合数量、错误提示及提交操作区。

弹窗可以通过取消按钮或右上角关闭按钮返回候选视角页面。提交期间关闭操作禁用，避免重复提交和状态歧义。

### 4.2 装修风格

首版提供十二种风格：

1. 现代简约
2. 现代轻奢
3. 清新奶油
4. 原木自然
5. 新中式
6. 北欧清新
7. 日式侘寂
8. 法式奶油
9. 意式典雅
10. 中古复古
11. 美式经典
12. 工业风

默认展示前八种，通过“展开更多”显示其余四种。每张卡片包含自行生成的真实室内参考图、风格名称和一句特征说明。选中状态使用蓝色描边与勾选标识。风格支持多选，默认选中“现代简约”。

风格名称参考公开的常见家装分类体系，但示意图、提示词和产品数据均由本项目自行维护，不复制第三方专有素材。

### 4.3 光照环境

首版提供：

- 晴天日间
- 阴天柔光
- 暖色黄昏
- 夜间氛围

环境支持多选，默认选中“晴天日间”。环境同时控制提示词中的天气、时间、室内灯光和窗外光照描述，不修改相机位置或空间结构。

### 4.4 组合与上限

预计图片数按以下公式实时计算：

```text
有效视角数量 × 已选风格数量 × 已选环境数量
```

视角、风格和环境任一为空时禁止提交。单次最多提交 24 张；超过上限时禁用“确认并生成”，并提示减少风格或环境。上限由服务端目录接口返回，前端不写死业务值。

条件草稿按 `planId + planVersion` 保存，重新进入时恢复上次选择。目录项失效时自动移除失效选择，并确保至少恢复服务端默认项。

## 5. 系统架构

### 5.1 组件边界

- `AiGenerationCatalog`：定义风格、环境、默认项和组合上限的稳定数据模型。
- `AiGenerationConditionsDialog`：负责弹窗渲染、多选、展开状态、校验和组合数量展示。
- `AiGenerationConditionStore`：按方案版本保存条件草稿，不保存 API Key。
- `AiViewCaptureService`：逐个切换固定视角并采集白模输入图，恢复采集前相机状态。
- `AiGenerationClient`：只访问同源 `/api/ai-concept/*`，处理提交、轮询、取消和重试。
- `AiGenerationJobStore`：管理前端任务列表、项目状态和白模/结果关联。
- Node `AiGenerationServer`：验证请求、拆分组合、持久化任务并调度 OpenAI 调用。
- Node `OpenAiImageClient`：封装 `gpt-image-2` 图像编辑请求和错误映射。
- Node `AiGenerationRepository`：保存任务元数据、输入图、结果图和恢复索引。

每个模块只暴露稳定接口。UI 不感知 OpenAI 请求格式，OpenAI 客户端也不读取页面状态。

### 5.2 同源与密钥

浏览器统一请求 `/api/ai-concept/*`。开发环境由 Vite 将 `/api` 代理到项目内 Node 服务；生产环境由同一站点提供页面和 API。因此正式页面不存在浏览器到 OpenAI 的跨域请求。

Node 服务只从 `OPENAI_API_KEY` 环境变量读取密钥，不接受前端传入的密钥，不把密钥写入日志、错误响应、任务数据或构建产物。接口仅支持固定的 AI 生图业务操作，不提供任意 URL 代理。

## 6. API 契约

### 6.1 获取目录

```text
GET /api/ai-concept/catalog
```

返回：

- 风格列表：`id`、名称、说明、参考图 URL、排序、启用状态。
- 环境列表：`id`、名称、说明、排序、启用状态。
- 默认风格和默认环境。
- `maxImagesPerJob`，首版为 24。
- 服务是否已配置可用。

### 6.2 创建任务

```text
POST /api/ai-concept/jobs
```

请求关联：

- `planId`、`planVersion`、白模版本。
- 所有合法视角的稳定 ID、房间、相机参数及白模截图。
- 所选风格 ID 和环境 ID。
- 客户端生成的提交请求 ID。

服务端重新计算组合数并执行上限校验，不能信任前端计算结果。创建成功后返回 `jobId`、任务项摘要和初始状态。

### 6.3 查询任务

```text
GET /api/ai-concept/jobs/:jobId
```

返回总体状态、完成数量、失败数量、取消数量，以及每个组合的视角、房间、风格、环境、输入图、结果图、错误和时间信息。

### 6.4 重试和取消

```text
POST /api/ai-concept/jobs/:jobId/items/:itemId/retry
POST /api/ai-concept/jobs/:jobId/cancel
```

重试只作用于失败或已取消的单项。取消只阻止尚未开始的任务；已经完成的结果保留，正在向 OpenAI 请求的任务标记为取消请求中，并在响应结束后不再启动后续项。

## 7. 任务拆分与 OpenAI 调用

### 7.1 组合矩阵

服务端将每个“视角 × 风格 × 环境”拆成独立项目。项目使用以下内容生成幂等键：

```text
planId + planVersion + whiteModelVersion + viewId + styleId + environmentId + inputImageDigest
```

相同幂等键已有成功结果时复用该结果；已有执行中任务时返回原任务引用。只有设计师明确发起重新生成时才创建新的尝试版本。

### 7.2 输入图采集

前端按稳定顺序采集所有合法视角。每次采集前应用该视角的位置、朝向和水平 FOV，并等待场景与材质稳定。截图不包含 UI、小地图、房间 Sprite、选择框或调试信息。

采集失败时记录具体房间和视角，不提交该视角。采集结束后恢复用户提交前的相机和页面状态。

### 7.3 图像编辑提示词

每个任务把白模截图作为高保真图像输入，使用 `gpt-image-2` 的图像编辑能力。提示词由共享结构约束、风格描述和环境描述组成。

共享约束要求：

- 保留相机视点、透视、画面边界和视场角。
- 保留房间尺寸、墙体、门窗、吊顶和主要固定构件。
- 保留主要家具的位置、尺度和数量关系。
- 只改变材质、软装表现、色彩、装饰细节和光照氛围。
- 输出真实室内摄影语义，不生成平面图、轴测图、拼贴、文字、水印或人物。

风格描述来自服务端目录，环境描述来自环境目录，前端不拼接自由格式的模型提示词。

### 7.4 调度

首版 Node 队列最大并发数为 2。并发数通过服务端配置调整，不由前端控制。任务项完成后立即持久化并可查询，不等待全部组合结束。

## 8. 数据与持久化

任务数据和图片保存在 `occt_demo` 的运行数据目录，不写入源码目录，也不提交 Git。目录按方案、版本和任务隔离。

每个任务至少保存：

- 方案、版本和白模版本。
- 创建时间、更新时间、总体状态。
- 所选条件快照。
- 每个项目的幂等键、视角、房间、风格、环境和状态。
- 输入图摘要及受控文件引用。
- 输出图受控文件引用。
- OpenAI 请求标识、用量摘要和标准化错误，不保存密钥。

服务重启后扫描任务索引。执行中的项目恢复为可重试中断状态；已完成图片继续可用，等待中的项目可以按原顺序恢复。

## 9. 状态与错误处理

### 9.1 弹窗状态

- `loading`：加载目录和条件草稿。
- `ready`：条件合法且可提交。
- `invalid`：条件为空、视角为空或超过上限。
- `submitting`：采集输入并创建任务。
- `submit-error`：提交失败，可保留条件后重试。

### 9.2 任务状态

- 总体：`queued`、`running`、`completed`、`partial`、`failed`、`cancelled`。
- 单项：`queued`、`running`、`completed`、`failed`、`cancelled`、`interrupted`。

### 9.3 错误策略

- 缺少 `OPENAI_API_KEY`：提交前返回明确配置错误，不创建任务。
- 认证、额度和内容安全错误：不自动重试，显示可操作原因。
- 限流、超时和临时网络错误：使用带抖动的指数退避进行有限次数重试。
- 单项失败：不阻断其他组合，最终任务状态为 `partial` 或 `failed`。
- 输入截图无效：标记具体视角，用户返回候选页修正。
- 重复提交：根据请求 ID 和幂等键返回已有任务，不重复计费。
- 服务不可用：保留条件草稿，允许稍后重新提交。

错误响应不得包含 API Key、完整上游响应头或本机绝对路径。

## 10. 测试与验收

### 10.1 单元测试

- 十二种风格、四种环境、默认项和排序稳定。
- 组合数量计算正确，空条件和超过 24 张被拒绝。
- 条件草稿按方案版本隔离并正确恢复。
- 幂等键在输入不变时稳定，任一关键输入变化时不同。
- OpenAI 错误正确映射为可重试和不可重试类型。
- 队列并发不超过 2，取消不启动新项目。

### 10.2 组件与接口测试

- 弹窗打开、关闭、展开、多选、默认选择和提交状态正确。
- 风格参考图失败时显示稳定占位，不影响选择。
- 服务端重新执行组合上限和输入校验。
- API Key 不出现在前端包、接口响应、日志和持久化文件中。
- 创建、查询、取消、单项重试和服务重启恢复正确。

### 10.3 页面回归

- 候选视角浏览、微调、新增和删除继续正常。
- 弹窗不会恢复已删除或非法视角。
- 截图不包含 UI、Sprite 或调试辅助内容。
- `index-3d.html`、`index-panorama.html` 和现有构建继续通过。

### 10.4 真实接口最小验收

使用有效的 `OPENAI_API_KEY` 提交：

```text
1 个合法视角 × 1 个风格 × 1 个环境 = 1 张图片
```

验收结果必须：

- 成功调用 `gpt-image-2` 图像编辑接口。
- 保持输入白模的相机视角和主要空间结构。
- 明确体现所选风格与环境。
- 可以追溯到方案版本、房间、视角、风格和环境。
- 刷新页面后仍能恢复任务和结果。

## 11. 未来 CAD 集成边界

未来迁移 CAD Plugin 时保持前端的目录、任务和结果契约不变，由 CAD C++ 桥接承担密钥保护、网络请求与本地持久化。当前阶段不提前修改 CAD 工程，也不把 Node 实现复制到 CAD Plugin。
