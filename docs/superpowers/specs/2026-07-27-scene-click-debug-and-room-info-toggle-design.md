# 场景模型点击调试与房间信息弹窗切换设计

## 背景

3D 户型页面当前存在两个相邻的点击交互问题：

1. 参数化软装已经携带 `typeId`、`softlistId` 等标识，但现有 `SelectionManager` 只选择 `type === 'placedModel'` 的对象，无法通过点击查看参数化软装的解析和放置信息。
2. `RoomInfoView` 只保存弹窗 DOM，没有保存当前房间标识。每次点击房间都会重新执行 `_show()`、重建内容并移动弹窗，因此无法识别“再次点击同一房间应关闭”。

本次修改只增加调试可观测性和修正弹窗状态切换，不改变模型的几何、放置、材质或编辑行为。

## 目标行为

### 参数化软装点击调试

- 仅在 URL hash 为 `#debug` 时启用，与项目现有调试模式保持一致。
- 点击参数化软装时，在控制台输出一份结构化快照。
- 快照至少包含：
  - `typeId`
  - `softlistId` / 实例 ID
  - 类型名称和资源 ID（可用时）
  - JSON 基点和 footprint
  - JSON 旋转角度、水平翻转、上下翻转
  - 参数化模型参数
  - 模型原始尺寸、最终世界包围盒和世界位置
  - 缩放及放置偏移
- 不直接把完整 Three.js `Mesh` / `Group` 长期打印到控制台，避免开发者工具保留对象引用而阻碍垃圾回收。
- 非 Debug 模式下不新增控制台输出，也不改变点击行为。

### 房间信息弹窗

- 第一次点击房间 A：打开弹窗并显示 A。
- 弹窗显示 A 时再次点击 A：关闭弹窗。
- 弹窗显示 A 时点击房间 B：复用同一个弹窗 DOM，更新为 B 的内容并保持打开。
- 点击空白区域或关闭按钮：关闭弹窗并清空当前房间状态。
- 关闭后再次点击原房间：正常重新打开。

## 方案选择

### 房间状态

采用在 `RoomInfoView` 内维护 `activeRoomIndex` 的方案。房间点击时以命中对象的 `userData.roomIndex` 作为稳定标识，同时检查弹窗是否可见。

不采用以下方案：

- 比较 `roomInfo` 对象引用：依赖数据克隆和对象生命周期，语义不如房间索引明确。
- 把房间标识只放在 DOM 属性中：会让交互状态与展示层耦合。

### 点击仲裁

房间和参数化模型必须依据同一条射线的最近命中对象决定行为，不能分别只检测自己的目标集合。否则点击家具时，房间检测仍可能穿过家具命中下方地板，并错误打开房间弹窗。

在 `RoomInfoView` 的点击入口中统一收集以下可点击对象：

- `type === 'parametric-softlist'` 的可见 Mesh
- `type === 'floor'` 的地板
- `type === 'roomLabel'` 的房间标注

对合并后的集合执行一次递归射线检测，并按最近命中对象分流：

- 参数化软装：向上查找到参数化软装实例根组；Debug 模式下输出快照；不打开房间弹窗。
- 地板或房间标注：执行房间弹窗切换逻辑。
- 无命中：关闭房间弹窗。

为避免职责名称继续扩大，模型调试快照的构造和打印使用独立的纯函数/小模块；`RoomInfoView` 只负责点击仲裁和调用。

## 数据挂载

`ParametricModelLoader` 在每个实例根组的 `userData` 中保存可序列化的 `debugInfo` 快照。该快照从当前软装条目和实际放置计算结果生成，不保存 Three.js 对象引用。

需要从缓存模板继承的 `typeName`、`resId` 和默认尺寸在实例创建时复制到快照。最终世界包围盒在实例变换完成并更新矩阵后计算。

子 Mesh 保留 `typeId` 和 `softlistId`，点击命中后沿父级向上查找带有实例级 `debugInfo` 的根组，保证多 Mesh OBJ 只输出一个实例的信息。

## 状态转换

`RoomInfoView` 增加：

- `activeRoomIndex = null`
- `_isPanelVisible()`
- 统一的 `_hide()`：隐藏 DOM，并把 `activeRoomIndex` 复位为 `null`

房间命中处理：

1. 读取 `roomIndex` 和 `roomInfo`。
2. 若弹窗可见且 `roomIndex === activeRoomIndex`，调用 `_hide()`。
3. 否则设置 `activeRoomIndex = roomIndex`，并调用 `_show()` 更新同一个面板。

`_show()` 仍保持 DOM 幂等创建；切换房间只替换内容，不创建第二个 `.room-info-panel`。

## 错误与边界处理

- 命中对象没有 `roomInfo`：关闭弹窗，不抛错。
- 命中对象没有 `roomIndex`：不以房间名称作为主键；关闭弹窗并记录开发态警告。
- 参数化模型缺少部分调试字段：以 `null` 或空数组输出，不影响点击。
- 模型还在异步加载：只检测已经加入场景的实例。
- 点击后拖动超过现有 5px 阈值：继续视为相机拖拽，不触发模型日志或房间切换。
- 面板内部的画布缩放、拖动和关闭按钮不应冒泡成 3D 场景点击。

## 测试策略

### 自动化测试

为状态逻辑提取可测试的决策函数，先编写失败测试，再实现：

- 无活动房间 + 点击 A => `show A`
- A 已显示 + 点击 A => `hide`
- A 已显示 + 点击 B => `show B`
- 隐藏后再次点击 A => `show A`
- 点击空白 => `hide`
- 最近命中为参数化软装 => 不显示底层房间
- Debug 关闭 => 不打印模型信息
- Debug 开启 => 打印一次结构化快照，且不包含 Mesh/Group 引用
- 多 Mesh 模型任一子网格命中 => 解析到同一个实例根组

### 浏览器验证

使用 `index-3d.html#debug` 启动页面并验证：

1. 点击同一房间两次，确认弹窗打开后关闭，DOM 中始终最多只有一个 `.room-info-panel`。
2. 依次点击两个不同房间，确认弹窗内容切换且旧房间信息消失。
3. 点击软装模型，确认控制台输出正确 `typeId`、基点、旋转、翻转和包围盒，且不弹出底层房间信息。
4. 去掉 `#debug` 后点击模型，确认不新增模型调试日志。
5. 拖动相机和操作房间俯视图，确认不会误触发点击。

## 非目标

- 不让参数化软装接入 TransformControls，也不允许通过本次点击直接移动、旋转、缩放或删除它。
- 不改变软装放置算法和房间尺寸计算。
- 不增加新的可见调试面板。
