# 全景页水平 FOV 投影换算设计

## 背景

CAD JSON 中 `camera_list[].BlockInnerInfo.FOV` 来自 UE 的相机 `FieldOfView`。UE 在导出点位时还会记录 `AspectRatio`，该 FOV 表示设计师视角的水平视场角。Three.js `PerspectiveCamera.fov` 表示垂直视场角。当前实现把 JSON 值直接写入 Three.js，导致 16:9 画面中 `FOV=90` 实际呈现约 121 度的水平视野，墙体、门窗与家具在画面边缘发生明显拉伸。

## 目标

- 点位数据、持久化数据及编辑状态中的 `fov` 始终保持水平 FOV 语义。
- 渲染时根据实时画布宽高比换算成 Three.js 所需的垂直 FOV。
- 浏览器尺寸变化后保持相同的水平视野，避免窗口比例影响设计视角。
- 点位切换、平滑移动、复位视角、设置进入视角和位置微调使用同一换算逻辑。
- 不改变普通 3D 浏览模式的相机行为。

## 方案选择

### 采用：投影边界统一换算

在 `SceneManager` 的全景点位相机边界增加独立的水平到垂直 FOV 换算函数。所有写入 Three.js 相机的点位 FOV 都经该函数处理；所有从相机读回并保存到点位的数据都转换回水平 FOV。

公式：

```text
verticalFov = 2 * atan(tan(horizontalFov / 2) / aspect)
horizontalFov = 2 * atan(tan(verticalFov / 2) * aspect)
```

优点是数据语义稳定、与 UE 导出一致，并且可正确适配不同屏幕比例。

### 未采用：把所有点位 FOV 固定成 60 度

能快速减轻形变，但会丢失设计师设置的广角和特写差异，也无法适配屏幕比例。

### 未采用：改用正交投影

正交投影没有真实的近大远小关系，不适合室内漫游和全景视角展示。

## 数据流

1. `PanoramaPointModel` 从 JSON 读取水平 FOV，不做投影语义转换。
2. 进入点位或切换点位时，`SceneManager` 按当前画布宽高比将水平 FOV 转成垂直 FOV，再更新 `PerspectiveCamera`。
3. 平滑切换在水平 FOV 空间插值，每帧换算后写入相机，避免过渡语义随屏幕比例变化。
4. 用户滚轮缩放时先修改水平 FOV，再换算到相机；保存进入视角或微调时读回水平 FOV。
5. 窗口尺寸变化时重新应用当前水平 FOV，以保持构图的水平覆盖范围不变。

## 数值与容错

- 延续现有点位范围，将水平 FOV 限制在 30–120 度。
- 宽高比无效或画布高度为零时使用相机当前有效宽高比；仍不可用时回退到 16:9。
- `FOV=90` 在 16:9 下换算为约 58.72 度垂直 FOV。
- 不使用 JSON 中历史 `AspectRatio` 驱动当前投影；该字段描述保存时环境，实时页面应使用当前画布比例。

## 测试与验收

- 单元测试覆盖 16:9、4:3 和无效宽高比下的双向换算。
- SceneManager 测试验证进入、切换、平滑过渡、滚轮缩放和读取姿态均保持水平 FOV 语义。
- 调整窗口比例后，水平构图范围保持不变。
- 完整测试和 `build:3d` 通过。
- 浏览器中对比修复前后：画面中心构图不突变，边缘墙体与家具拉伸显著减轻。

## 非目标

- 本次不调整相机点位坐标、高度、朝向和室外环境。
- 本次不修改离线六视图或等距柱状全景图的生成算法。
- 本次不修改 CAD Plugin。
