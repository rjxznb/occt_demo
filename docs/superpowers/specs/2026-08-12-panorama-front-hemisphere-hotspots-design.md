# 全景页前半球热点过滤设计

## 背景

当前 `projectPanoramaHotspot()` 会将相机后方的点位方向反转，再把提示固定到屏幕边缘。因此用户即使背对某个点位，仍会看到该点位的导航提示，容易误判空间方向。

## 目标

- 只显示当前相机前方和左右侧面的点位提示。
- 相对当前视线方向超过 90 度、位于后半球的点位完全隐藏。
- 位于前半球但超出当前屏幕视锥的点位继续显示边缘方向提示。
- 正好位于左右侧向 90 度边界的点位保留，避免侧面导航消失。
- 旋转相机时热点实时出现或隐藏。
- 不修改点位数据，不影响小地图、点位切换和 WASD 导航。

## 方案

### 投影结果增加可见性语义

`projectPanoramaHotspot()` 根据点位的相机局部坐标判断半球：Three.js 相机朝向局部 `-Z`，因此 `local.z <= 0` 属于前半球，`local.z > 0` 属于后半球。

函数返回值增加 `visible`：

- 前半球且在视锥内：`visible: true, inView: true`，显示在真实屏幕投影位置。
- 前半球但不在视锥内：`visible: true, inView: false`，显示在屏幕边缘并保留方向箭头。
- 后半球：`visible: false, inView: false`，不再计算或展示误导性的反转方向。

`PanoramaHotspots.update()` 每帧依据 `projection.visible` 切换单个按钮的 `hidden` 状态。重新进入前半球时恢复显示，并继续更新位置、角度和 `is-offscreen` 状态。

## 边界与容错

- 使用一个极小浮点容差处理接近 90 度的点，确保精确侧向点仍可见。
- 点位与相机位置重合时不显示提示，避免方向没有定义时出现随机箭头。
- 总热点开关仍优先控制整个容器；单点半球过滤不改变用户的开关选择。

## 测试与验收

- 投影单元测试覆盖正前方、视锥外侧面、精确 90 度、后方和与相机重合五种情况。
- 组件测试验证后方按钮被隐藏，旋转相机使其进入前半球后恢复显示且可以点击。
- 完整测试及 `build:3d` 通过。
- 浏览器中从一个点位旋转一周：前方热点正常显示，侧面热点停靠边缘，越过后半球边界即隐藏，不出现方向反转。

## 非目标

- 不按房间、距离或遮挡关系进一步筛选点位。
- 不改变热点样式、文字或点击后的点位切换动画。
- 不修改普通 3D 页面和 CAD Plugin。
